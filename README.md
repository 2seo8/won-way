# WON길

**금융 문의를 이해하고, 정책에 근거해 가장 적절한 상담 경로를 안내합니다.**

사용자의 자연어 문의를 분석한 뒤, 정책 데이터와 고객 상황을 검증하여 상담 채널과 업무 경로를 추천하는 AI 금융 상담 서비스입니다.

> 현재는 프로토타입입니다. 실제 금융거래·상담 연결·예약을 실행하지 않으며, 테스트 가능한 시나리오가 제한되어 있습니다.

## Tech Stack

## 동작 방식

1. 사용자가 자연어로 금융 문의를 입력합니다.
2. AI가 문의에서 의도와 조건 변경분을 원문 근거와 함께 추출합니다.
3. 서버가 근거를 검증하고 이전 조건과 병합한 뒤, 정책을 조회합니다.
4. 부족한 조건은 추가 질문으로 확인합니다.
5. 챗봇·전화·이메일 등 채널을 평가해 적합한 상담 경로를 추천합니다.

## AI Agent

WON길의 AI는 **"언어를 이해하는 일"만 맡고, 판단은 서버가 합니다.** 모델이 정책이나 채널을 직접 정하지 않기 때문에 답변이 정책 데이터에 근거하고, 같은 조건이면 같은 결과가 나옵니다.

### 역할 분담

| 단계 | 담당 | 하는 일 |
| --- | --- | --- |
| 1. 문의 해석 | AI (LLM) | 고객 문장에서 업무 의도와 확인된 조건의 변경분을 구조화해 추출 |
| 2. 근거 검증 | 서버 | 추출값마다 원문 근거(evidence)가 실제 메시지에 있는지, 허용된 필드인지 검사 |
| 3. 조건 병합 | 서버 | 이전 확인 조건과 병합. 정정은 덮어쓰고, 다른 업무로 바뀌면 이전 조건 초기화 |
| 4. 정책 조회 | 서버 | 정책 DB에서 기간·고객·상품·상황 조건을 비교해 일치/불일치/미확인으로 판정 |
| 5. 추가 질문 | 서버 | 답을 바꾸는 누락 조건만 묶어서 질문 (`FOLLOW_UP`) |
| 6. 채널 평가 | 서버 | 챗봇·전화·이메일을 점수화해 순위와 이유 산출 |

### 환각을 막는 설계

- **원문 근거 필수**: 모델이 뽑은 모든 조건은 고객 메시지의 실제 문장을 근거로 가져야 하며, 근거가 없으면 버립니다.
- **추측 금지**: 말하지 않은 조건은 `false`가 아니라 "미확인"으로 둡니다. 예를 들어 받는 은행을 모르면 당행·타행을 가정하지 않고 되묻습니다.
- **정책 데이터 기준 안내**: 안내 절차와 유의사항은 모델이 지어내지 않고, 검증된 정책 분기에서만 가져옵니다.
- **세션 격리**: 대화 기록은 세션별로 분리되어 다른 세션의 내용이 섞이지 않습니다.
- **프롬프트 인젝션 방어**: 사용자 메시지 속 지시는 따르지 않도록 해석기에 명시하며, 정책·채널 판단은 모델 밖에서 이루어집니다.
- **민감정보 비저장**: 고객 원문과 추출값, 모델 답변은 로그에 남기지 않습니다. 대화는 서버 메모리에만 있다가 세션 종료나 재시작 시 사라집니다.

### 응답 유형

| 유형 | 의미 |
| --- | --- |
| `FOLLOW_UP` | 업무나 조건이 부족해 추가 질문을 하는 단계 (추천은 비움) |
| `GUIDANCE` | 정책에 근거한 방법·절차 안내 |
| `CHANNEL_RECOMMENDATION` | 검증이 끝나 상담 채널을 순위와 함께 추천 |
| `UNRESOLVED` | 현재 지원하지 않거나 확정할 수 없는 문의 |

### 채널 추천 방식

챗봇·전화·이메일을 모두 후보로 두고 상황에 맞춰 점수를 매깁니다. 업무별로 정해진 채널표가 아닙니다.

- 평가 항목: 상담 목적 지원 여부, 응답 방식, 이용 조건, 문답 적합성, 고객의 명시적 선호
- 긴급하거나 실시간 대화가 필요하면 전화·챗봇이, 급하지 않고 비동기 답변을 받아들이면 이메일이 올라갑니다.
- 앱 처리에 실패했거나 사람 상담을 원하는 경우도 챗봇을 제외하지 않고 순위만 낮춥니다.
- 채널 운영 상태를 확인하지 못하면 "가능"으로 단정하지 않고 미확인으로 표시합니다.
- 고객 화면에는 내부 점수 항목 대신 채널의 지원 범위와 확인된 이용 조건을 이유로 보여 줍니다.

### 사용 기술

- Spring AI `ChatClient`로 모델을 호출하고, 결과를 정해진 구조(structured output)로 받습니다.
- 정책 조회와 채널 평가는 `@Tool`로 노출되는 서버 로직(`ConsultationTools`)과 연결됩니다.
- 모델이 받는 입력 형식은 `tool-input-catalog.json` 카탈로그로 관리합니다.

> 현재 정책 데이터는 모두 `DRAFT` 상태이고, 전화·이메일 운영정보는 데모용입니다. 실제 계좌 조회와 거래 실행은 지원하지 않습니다.

## 빠른 시작

백엔드를 먼저 실행한 뒤 프런트엔드를 실행합니다. DB·모델 연결 정보는 실행 환경에서 직접 제공해야 하며, 비밀값은 Git에 포함하지 않습니다.

```sh
# 1. backend (Windows PowerShell)
cd backend
.\gradlew.bat bootRun
```

```sh
# 2. frontend
cd frontend
npm ci
npm run dev -- --port 5173
```

브라우저에서 <http://127.0.0.1:5173> 에 접속합니다. 자세한 설정(`.env.local` 등)은 각 폴더의 README를 참고하세요.
